P	1. 產品目標與治理邊界
P	把 QA 評分標準的版本、維度、門檻、必檢項目、部門適用性、Gate Policy、Impact 與 Approval 放在單一治理頁中，避免標準散落在各 QA 工作區。
P	ACTIVE Criteria Version 不可原地修改；任何實質變更先形成新版本／新草稿，再進 Impact、Review 與 Approval，歷史審查結果永久保留原 criteria_version。
P	SG-02 只治理「審查標準」；專案、任務、影片、素材的實際 QA 執行仍由 QA Runtime / QA-01 負責。
P	Threshold 不得硬編碼在 UI、前端常數或 QA 執行頁；QA Runtime 必須讀取被正式綁定的 Criteria Version / Gate Policy。
P	未註冊 Search / Filter / Export / Clone / Delete / Activate 等操作不得因便利性自行加入。

P	5. Entity Hierarchy & Version Semantics
P	QualityCriteriaVersion 是版本根；Dimension / Threshold / Required Check / Department Mapping / Gate Policy 的正式狀態必須可追溯回該版本。
P	ACTIVE 版本為 immutable。修改需求先建立新的 Draft/Working Version，不允許把 ACTIVE row 直接改寫。
P	Review Result 必須保存 criteria_version_ref；後續 Criteria 更新不能回填或重算歷史結果，除非建立正式 Revalidation 結果且保留原結果。
P	同一時點可存在歷史版本與待核准版本，但執行端只使用被 Current Mapping 明確指定的版本；不得用 latest/current 字串猜測。
P	SUPERSEDED 代表不再作為新工作的預設版本，但仍可被歷史 Review Result 引用；RETIRED 仍保留 Audit/Lineage。

P	20. Definition of Done / Construction Handoff
P	Static Design：Page / Section / Control / Field / Layout / State / Error / Permission / Action / Gate / Interaction / Visual Geometry 已可施工。
P	Functional Closure：Configure / Approve / Criteria Consumption / Historical Reproducibility / Impact / Revalidation 均有前後關聯，不留下「先做畫面、後補邏輯」的空洞。
P	Runtime Enablement：仍須由施工階段核對 Governance operation runtime、QA runtime mapping、DB persistence、permission assignment、audit、tests 與 deployment evidence；本 Word 不宣稱 Production Ready。
P	任何實際施工發現未註冊功能（例如 Clone / Search / Export / Activate / Retire command），不得從本文件猜 API；必須回到 Current Authority 走正式補權威流程。
P	施工交付結論｜SG-02 的設計目標不是「做一張 QA 標準表」，而是把 Criteria 的版本治理、Impact、Approval、歷史可重現性與 QA Runtime 綁定做成完整閉環；UI 保持單頁、低頻細節 Drawer 化、效應操作 Modal 化。
