P	15. Permission Materialization / L1 → Explicit Assignments
P	1. 讀取 Draft 中選定的前台／後台 L1。
P	2. 對每個 L1 解析其當下正式註冊的 resource / action / scope / condition 集合。
P	3. 展開成 Account Permission Assignment candidate rows；禁止 runtime parent/child inheritance。
P	4. 與目標帳號 current explicit assignments 做 diff。
P	5. 產生 Authorization Impact Preview：Added / Removed / Unchanged / Blocked。
P	6. 要求 explicit confirmation。
P	7. Additions 使用 assign；Removals 使用 revoke；帶 expected_version / correlation / idempotency / audit。
P	8. 全部 required operations 成功後才允許 COMPLETE。
P	9. Grant / Revoke 後刷新 Effective Permission 與 Navigation projection。
P	Silent Future Grant 禁止：某 L1 日後新增 resource/action，不會自動授權既有帳號。必須重新編輯、Preview、明確 Apply。
