P	4. Login Functional Chain
P	1. 使用者開啟 `/login`。
P	2. Locale Provider 載入目前語言；登入頁不需要 Page Permission。
P	3. 使用者輸入 email + password，送出 `POST /identity/login`。
P	4. Server 以 email 尋找 READY runtime account；密碼使用 scrypt 驗證。
P	5. 建立 32-byte random session token；資料庫只保存 SHA-256 token hash。
P	6. 以 session 對 runtime account → app_users 做 email join；app_users 必須 `disabled_at IS NULL`。
P	7. 成功：建立 `acpos_session` HttpOnly Cookie，303 Redirect `/`。
P	8. 失敗：回 `/login?error=<reason_code>`；頁面顯示實際錯誤狀態，不建立 Session。

P	6. Security Contract
P	Cookie 必須 HttpOnly；Production / HTTPS 時 Secure；SameSite=Lax。
P	Database 永遠只保存 session token 的 SHA-256 hash，不保存 raw token。
P	Password 使用 scrypt N=16384 / r=8 / p=1 / keylen=32；失敗路徑使用 dummy hash 降低帳號枚舉 timing 差異。
P	登入失敗不得回傳 password、password hash、session token、header plaintext 或 secret。
P	不得把 x-correlation-id、Authorization Bearer、第三方 IdP Header 猜成 Current Identity。
P	Runtime account 必須 READY，且可映射至 non-disabled app_users；否則 fail-closed。
